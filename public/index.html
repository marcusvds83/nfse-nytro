Producao / Homologacao

O middleware opera em polling: a cada 15 segundos, busca faturas com x_nytro_nfse_status = 'pendente' no Odoo, gera o XML DPS, assina com certificado A1, envia à SEFIN, e atualiza o Odoo com o resultado.

Fluxo de Emissao NFS-e (passo a passo)

  1. Odoo: Usuario clica no botao "Emitir NFS-e" (Server Action marca x_nytro_nfse_status = 'pendente')
  2. Middleware (polling): Detecta fatura pendente via XML-RPC
  3. Middleware: Le dados da fatura, empresa, parceiro, produtos e impostos
  4. Middleware: Gera XML DPS v1.01 com todos os campos obrigatorios
  5. Middleware: Assina XML com XMLDSig RSA-SHA256 (certificado A1 do Firebase)
  6. Middleware: Comprime XML com GZip, codifica em Base64, envia via POST para SEFIN com mTLS
  7. SEFIN: Valida XML, processa DPS, retorna XML de resposta com chave de acesso e numero
  8. Middleware: Atualiza campos no Odoo (status, numero, chave, protocolo, data, XML)
  9. Middleware: Anexa XML ao chatter da fatura
  10. Middleware: Gera PDF DANFSe (PDFKit com logo Nytro) e anexa ao chatter

Fluxo de Cancelamento NFS-e (passo a passo)

  1. Odoo: Usuario clica em "Cancelar NFS-e" (Server Action marca x_nytro_nfse_status = 'cancelar_solicitado')
  2. Middleware (polling): Detecta fatura com status cancelar_solicitado
  3. Middleware: Le a chave de acesso (x_nytro_nfse_codigo_verificacao)
  4. Middleware: Gera XML pedRegEvento v1.01 com evento e101101
  5. Estrutura: <pedRegEvento> > <infPedReg Id="PRE+chave+101101"> > tpAmb, verAplic, dhEvento, CNPJAutor, chNFSe, e101101
  6. e101101: xDesc = "Cancelamento de NFS-e" (obrigatorio), cMotivo (1/2/9), xMotivo (min 15 chars)
  7. Middleware: Assina infPedReg com XMLDSig RSA-SHA256
  8. Middleware: GZip+Base64, POST para /SefinNacional/nfse/{chave}/eventos
  9. SEFIN: Registra evento de cancelamento com data/hora
  10. Middleware: Atualiza Odoo: status = 'cancelada' ou volta para 'autorizada' se falhou

Guia de Implementacao para Novo Cliente

Para replicar este emissor NFS-e em outro cliente, siga estes passos na ordem:

  1. Clonar o repositorio
    git clone https://github.com/marcusvds83/nfse-nytro.git
    cd nfse-nytro
    npm install
  2. Criar novo servico no Render
    Novo Web Service apontando para o repo. O Render faz deploy automatico.
  3. Criar projeto no Firebase
    Console Firebase → Novo Projeto → Firestore Database (modo de teste) → Adicionar SDK Admin → Gerar chave privada (JSON) → Baixar o arquivo JSON.
  4. Configurar variaveis de ambiente no Render (todas obrigatorias):
    API_KEY=uma-chave-secreta-para-o-painel ODOO_ENABLED=1 ODOO_URL=https://cliente.odoo.com ODOO_DB=cliente-production-12345 ODOO_USER=admin@cliente.com ODOO_API_KEY=a1b2c3d4e5f6... NFSE_TP_AMB=2 (2=homologacao primeiro, depois mude para 1) NFSE_CIDADE=Curitiba NFSE_UF=PR NFSE_CODIGO_IBGE=4106902 NFSE_IM=123456789012 NFSE_ALIQUOTA_ISS=5.00 NFSE_C_TRIB_NAC=080201 NFSE_C_NBS=122051900 NFSE_OP_SIMP_NAC=3 NFSE_P_TOT_TRIB_SN=6.00 FIREBASE_PROJECT_ID=meu-projeto-firebase FIREBASE_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\nMIIEvgIBADANBg...\n-----END PRIVATE KEY-----\nFIREBASE_CLIENT_EMAIL=firebase-adminsdk-xxxx@meu-projeto.iam.gserviceaccount.com FIREBASE_CERT_COLLECTION=certificados FIREBASE_CERT_DOC_ID=cliente-a1
  5. Fazer deploy — o Render detecta o push e faz deploy automatico. Verifique os logs.
  6. Abrir o painel — acesse https://seu-servico.onrender.com, insira a API_KEY definida acima.
  7. Aba Setup (esta aba): faca upload do certificado A1 (arquivo .pfx + senha). O certificado e salvo no Firebase e persiste entre deploys.
  8. Aba Setup: faca upload da logo da empresa (PNG). A logo aparece no DANFSe gerado pelo middleware.
  9. Aba Campos Odoo: clique "Verificar Campos" para checar, depois "Criar Campos Ausentes". Isso cria os 16 campos x_nytro_* no Odoo.
  10. Aba Campos Odoo: clique "Criar Server Actions". Isso cria as acoes de Emitir e Cancelar NFS-e no Odoo.
  11. No Odoo: adicione os botoes das Server Actions na view de fatura. Va em Configuracao → Tecnico → Server Actions, encontre as acoes criadas, e adicione na view de account.move.
  12. Aba Impostos: configure os impostos por produto (codigo tributacao, NBS, aliquota ISS, retencao) e clique "Enviar ao Odoo".
  13. Testar em homologacao (NFSE_TP_AMB=2): crie uma fatura de teste, clique em Emitir NFS-e, verifique os logs e o resultado no gov.br.
  14. Mudar para producao: altere NFSE_TP_AMB=1 nas variaveis de ambiente no Render. Reinicie o servico.

Server Actions Prontas

As Server Actions abaixo sao criadas automaticamente no Odoo:

Nytro: Solicitar Emissao NFS-e
Modelo: account.move | Acao: Executar codigo Python
if record.state != 'posted':
    record.action_post()
record.x_nytro_nfse_status = 'pendente'
record.x_nytro_nfse_erro = False
record.x_nytro_nfse_mensagem = False
Nytro: Solicitar Cancelamento NFS-e
Modelo: account.move | Acao: Executar codigo Python
if record.x_nytro_nfse_status == 'autorizada':
    record.x_nytro_nfse_status = 'cancelar_solicitado'
else:
    raise UserWarning('Apenas NFS-e autorizadas podem ser canceladas.')

Apos criar, adicione os botoes na view de fatura manualmente ou via vista herdada (inherit view).

Deploy para Outro Cliente

Para replicar o emissor NFS-e em outro cliente Odoo, siga os passos:

  1. Faca o deploy deste middleware em uma nova instancia (novo repo Render ou novo servico)
  2. Configure as variaveis de ambiente: ODOO_URL, ODOO_DB, ODOO_USER, ODOO_API_KEY do novo cliente
  3. Configure NFSE_IM, NFSE_CIDADE, NFSE_CODIGO_IBGE, NFSE_UF conforme o municipio
  4. Faça o upload do certificado A1 do novo cliente via POST /api/v1/nfse/certificado
  5. Faça o upload da logo do novo cliente via POST /api/v1/nfse/certificado/logo
  6. Clique em "Verificar Campos" nesta aba e depois "Criar Campos Ausentes"
  7. Clique em "Criar Server Actions" para gerar os botoes de emitir/cancelar
  8. Configure os impostos na aba "Impostos" (aliquota, NBS, codigo tributacao)
  9. Teste com uma fatura de homologacao (NFSE_TP_AMB=2)
